# MultiplayerSynchronizer Compatibility Tests

Tests that verify our implementation works with **actual** Godot MultiplayerSynchronizer, not just the specification.

## Overview

These tests verify that:
1. Our encoded variants can be decoded by MultiplayerSynchronizer's actual decoding methods
2. Our full sync packets match the format MultiplayerSynchronizer expects
3. Our delta sync packets match the format MultiplayerSynchronizer expects
4. The packet structure can be processed by MultiplayerSynchronizer's receive handlers

## Test Files

### Elixir → MultiplayerSynchronizer

1. **`test_multisync_packet.exs`**: Generates a full sync packet in MultiplayerSynchronizer format
2. **`test_multisync_delta_packet.exs`**: Generates a delta sync packet in MultiplayerSynchronizer format
3. **`test_multisync_compatibility.gd`**: Tests that MultiplayerSynchronizer can decode our packets

## Running the Tests

### Step 1: Generate Packets in Elixir

```bash
cd /path/to/bug-free-octo-parakeet

# Generate full sync packet
mix run thirdparty/godot-multiplayer-sync-test/test_multisync_packet.exs

# Generate delta sync packet
mix run thirdparty/godot-multiplayer-sync-test/test_multisync_delta_packet.exs
```

This creates:
- `elixir_full_sync_packet.bin` - Full sync packet
- `elixir_delta_sync_packet.bin` - Delta sync packet

### Step 2: Test in Godot

1. Open the project in Godot
2. Attach `test_multisync_compatibility.gd` to a node
3. Run the scene

The test will:
- Decode variants using `bytes_to_var()` (what MultiplayerAPI uses)
- Parse full sync packets using MultiplayerSynchronizer's `on_sync_receive()` logic
- Parse delta sync packets using MultiplayerSynchronizer's `on_delta_receive()` logic
- Verify packet structure matches what MultiplayerSynchronizer expects

## What These Tests Verify

### Test 1: Variant Decoding
- Uses `bytes_to_var()` to decode each variant (same as MultiplayerAPI)
- Verifies all variants decode successfully
- Confirms our encoding is compatible with MultiplayerSynchronizer's decoder

### Test 2: Full Sync Packet
- Reads packet generated by our Elixir encoder
- Parses using MultiplayerSynchronizer's `on_sync_receive()` logic:
  - Reads command byte
  - Checks for delta flag
  - Reads network time
  - Processes synchronizers (net_id, data_size, variant data)
  - Decodes variant data using `bytes_to_var()`
- Verifies packet structure matches MultiplayerSynchronizer's expectations

### Test 3: Delta Sync Packet
- Reads packet generated by our Elixir encoder
- Parses using MultiplayerSynchronizer's `on_delta_receive()` logic:
  - Reads command byte
  - Verifies delta flag is set
  - Processes synchronizers (net_id, indexes, data_size, variant data)
  - Decodes variant data using `bytes_to_var()`
- Verifies packet structure matches MultiplayerSynchronizer's expectations

### Test 4: Receive Handler Simulation
- Simulates MultiplayerSynchronizer's complete packet processing flow
- Verifies packet can be parsed end-to-end
- Confirms compatibility with actual MultiplayerSynchronizer code paths

## Success Criteria

All tests should:
- ✅ Successfully decode all variants
- ✅ Successfully parse packet headers
- ✅ Successfully extract synchronizer data
- ✅ Successfully decode variant data
- ✅ Match MultiplayerSynchronizer's expected format exactly

## Differences from Spec Tests

**Spec Tests** (`verify_documentation_format.exs`):
- Verify format matches documentation
- Test binary structure
- Verify type headers and flags

**MultiplayerSynchronizer Tests** (these tests):
- Verify actual compatibility with MultiplayerSynchronizer
- Test using MultiplayerSynchronizer's code paths
- Verify packets can be processed by MultiplayerSynchronizer's handlers
- Test end-to-end packet processing

## Live ENet Integration Testing

**Status**: ⏳ **In Progress** - Establishing baseline before interest management implementation

**Purpose**: Test MultiplayerSynchronizer compatibility with live network connections before implementing interest management/AOI filtering. This establishes a working baseline where all clients receive all data.

### Test Client

**File**: `test_live_enet_client.gd`

**Features**:
- Headless execution (extends `SceneTree`)
- ENet DTLS connection to Elixir server
- Connects to channel 0 (multiplayer sync)
- Sends `multiplayer_sync_request` packets at 64 Hz
- Receives and decodes MultiplayerSynchronizer packets
- Collects comprehensive metrics

**Usage**:
```bash
cd thirdparty/godot-multiplayer-sync-test
godot --headless --script test_live_enet_client.gd \
  --host 127.0.0.1 \
  --port 7777 \
  --duration 60 \
  --client-id 1 \
  --instance-id test_baseline
```

**Arguments**:
- `--host`: Server hostname (default: 127.0.0.1)
- `--port`: Server port (default: 7777)
- `--duration`: Test duration in seconds (default: 60)
- `--client-id`: Unique client identifier (default: 1)
- `--instance-id`: Instance ID for sync requests (default: test_baseline)

### Test Server Setup

**File**: `scripts/setup_test_server.exs`

**Purpose**: Creates avatar-like test nodes and starts ENet server

**Usage**:
```bash
mix run scripts/setup_test_server.exs --nodes 20 --port 7777 --instance-id test_baseline
```

**Arguments**:
- `--nodes` / `-n`: Number of avatar-like nodes to create (default: 20)
- `--port` / `-p`: Server port (default: 7777)
- `--instance-id` / `-i`: Instance ID for nodes (default: test_baseline)

**Node Structure**:
- **Transform** (position, rotation): Full sync at 64 Hz
- **Velocity** (Vector3): Delta sync when changed
- **Grounded** (bool): Delta sync when changed

### Multiple Clients Testing

**File**: `scripts/test_multiple_godot_clients.sh`

**Purpose**: Orchestrates testing with multiple concurrent clients

**Usage**:
```bash
./scripts/test_multiple_godot_clients.sh --clients 10 --duration 60 --nodes 20
```

**Arguments**:
- `--clients`: Number of concurrent Godot clients (default: 10)
- `--duration`: Test duration in seconds (default: 60)
- `--nodes`: Number of test nodes (default: 20)
- `--port`: Server port (default: 7777)
- `--instance-id`: Instance ID (default: test_baseline)

**What It Does**:
1. Starts Elixir test server with avatar-like nodes
2. Launches multiple Godot client instances
3. Monitors test execution
4. Collects and aggregates metrics
5. Generates JSON reports

**Output**:
- Results directory: `/tmp/multisync_test_results_<PID>/`
- Summary report: `summary.json`
- Metrics report: `metrics.json`
- Individual client logs: `client_<ID>.log`

### Metrics Collected

Each client collects:
- **Packet Statistics**: Count, total bytes, average size
- **Sync Rate**: Packets per second (target: 64 Hz ±2 Hz)
- **Latency**: Round-trip time in milliseconds (target: <20ms)
- **Correctness**: Data verification (received values match sent values)
- **Jitter**: Variation in packet timing
- **Network Time**: Tracks network time values for wrap-around testing

### Success Criteria

1. ✅ **Packet Format**: All packets decode correctly in Godot
2. ✅ **Full Sync**: 64 Hz sync rate maintained (±2 Hz tolerance)
3. ✅ **Delta Sync**: Only changed properties sent, bitmask correct
4. ✅ **Multiple Clients**: 10+ clients can connect simultaneously
5. ✅ **Data Correctness**: Received values match sent values
6. ✅ **Latency**: <20ms round-trip for VR requirements
7. ✅ **Stability**: No crashes or packet corruption over 5+ minute test

### Test Scenarios

**Scenario 1: Full Sync Baseline**
- All clients receive all nodes every frame
- Verify 64 Hz sync rate
- Verify packet format correctness
- Verify data accuracy

**Scenario 2: Delta Sync Baseline**
- Test with changing properties (velocity, grounded)
- Verify only changed properties sent
- Verify bitmask indexes correct
- Verify delta packets smaller than full sync

**Scenario 3: Multiple Clients Stress Test**
- 10+ concurrent clients
- All receiving same data (no filtering yet)
- Verify server handles load
- Verify no packet corruption

**Scenario 4: Long-Running Test**
- Run for extended period (5+ minutes)
- Verify network time wrap-around (65535 → 0)
- Verify no memory leaks
- Verify consistent performance
